The compile-only external view legalizes JVM names, exposes synthetic/bridge members, removes generic Signature attributes incompatible with Java lowered call syntax, and removes checked Exceptions attributes (Kotlin does not enforce Java checked exceptions). This view is never packaged; the running SDK uses unchanged upstream external dependencies. Original native source attribution is preserved in NOTICE/LICENSES, separately from the integration template's MIT license.

The output pass is ABI metadata restoration plus compiler-artifact removal, not a claim that no methods are removed. It deletes only Java implicit constructors absent from the original ABI after asserting the exact `()V; ALOAD 0; INVOKESPECIAL java/lang/Object.<init>()V; RETURN` body, no exception handlers, and no NEW/constructor-call references anywhere in the compiled SDK. Retained instruction bodies are not replaced. The UI currently has 21 such removals and 36 separately listed source-compiled private lambda forwarders.

The UI's 65 external artifacts are the dependency set resolved and frozen for this source-build experiment from the original SDK POM/BOM. A successful build proves compatibility with that exact recorded set, not all original release-time or current application consumer dependency resolutions.

The compile-only view additionally removes Java's @Target restriction from kotlinx.serialization.SerialName only. Kotlin emits this property annotation on synthetic JVM annotation methods that Java source cannot otherwise annotate. The original SDK annotations remain in recovered source; the original external runtime artifact is unchanged.

Read-only CaptureMappingPlugin exports actual Vineflower VarExprent/VarProcessor identities. ExportLambdaSites also records real bytecode offsets for unique diagnostic joins. SourceCaptureBindings parses lexical declarations without type attribution; it does not assert runtime equivalence. Explicit source-recovery ledgers retain constructor default coercion/nullability repairs, concrete continuation-local assignments, receiver-local rewrites and hand-restored coroutine state-machine branches. None of these tools copy original SDK Code attributes into a source-built artifact.

Return-only JVM overloads use exact owner/name/full-descriptor source aliases. The output pass resolves those aliases only against their original owner; inheritance fallback applies only to the pre-existing global `recovered$` normalizer names. Covariant bridge source removal is limited to original methods proved to be one same-owner typed call with ordered identical argument loads, ARETURN and no handlers, followed by actual javac regeneration and ABI/body comparison. It is not a blanket synthetic-method deletion.

Explicit private source helpers are exceptional recorded compilation aids. RestoreBuildMetadata accepts only exact owner/name/descriptor declarations in the optional text allowlist and requires exactly private static access, preserving their source-compiled Code. GalleryImage currently needs one such helper to retain check order before a Java delegating constructor call. Its product source explicitly preserves the constructor token in Kotlin NPE messages and filters only its own helper frame; differential tests must compare the resulting exception without test-side normalization.

The Nexus/Twig runtime JAR retains original inner-class metadata. Its base compile-only view removes nested declaration metadata so flat binary class names in recovered Java resolve; this view is never packaged. Realtime source builds use unchanged third-party classes, including original checked Exceptions declarations, rather than the lowered Kotlin compile view.

## Bounded Kotlin transition closure

The original two transition enums are restored in `source/android/intercom-sdk-base/kotlin/io/intercom/android/sdk/m5/navigation/transitions/TransitionStyle.kt`. Their 13 non-compilable split Java files were replaced, with hashes/provenance retained in `transition-enum-recovery.json` and diagnostic backups outside shipped source. The independent source-only entry is `scripts/android-build-transition-source.py --offline`; it reads only source, the 13-class text ABI, empty symbol-alias metadata, frozen eight compiler/six third-party library inputs and the existing metadata-restoration tool. It never reads an audit directory, reference SDK or original instruction body. Candidate compiler is Kotlin 2.1.20 with language/API 2.0, JVM target 1.8 and indy lambdas; this does not identify the original compiler patch version or change the App toolchain/runtime. Frozen compile libraries follow the already-resolved Compose 1.11.4 UI graph, which does not establish compatibility with every possible consumer version.

The first offline source-only build passes 13 classes and all expected ABI symbols, with no missing/extra symbols or added helper methods; artifact SHA-256 is `252f48a44f41b8d14a93577d686c4c653a691392d7cf96fb1e3dbb97bdc62b23`. The six original `transition$lambda$0` methods and marker constructors are generated naturally from Kotlin source. Independent original/raw-compiled/restored javap comparison preserved instructions, offsets, constants, complete symbolic descriptors and six bootstraps; output is version 52 without nest access. This is a small source closure, not full SDK or runtime acceptance. The compiler-generated Kotlin module currently describes only this closure; complete base module metadata remains part of the complete SDK build.

The main Java diagnostic uses a SHA-pinned copy of this source-built artifact and separately reports its 13 compiled classes/one Kotlin source, reducing its remaining Java target by 13. It does not count those classes as javac output or hide the failed main Java compilation. The original transition implementations are not present as compile dependencies.

Bytecode offsets in lambda/remember/SSA source-join ledgers refer to the SHA-pinned normalized diagnostic reference unless the evidence explicitly says raw vendor input. They are real offsets in that reference, rather than ASM instruction-list indexes. Reversible symbol normalization and ASM serialization can change constant-pool operand widths (a reviewed example shifts offsets by two bytes), so normalized and raw vendor offsets must not be conflated. Joins use complete descriptors, exact reference offsets and matching SSA exports from the same normalized input; raw-vendor comparisons retain their own coordinate. Normal source builds consume neither coordinate nor diagnostic reference jars.


## Normal complete Android artifacts

`scripts/android-build-artifacts.py` now prepares real AGP resource declarations, rebuilds all source closures, then assembles the original two resource namespaces into own base/UI AARs. The base component includes the independently source-built FCM service and SDK marker, merges the original FCM manifest service and original base/Nexus/FCM consumer keep rules, and declares frozen external runtime dependencies. The UI component keeps its original namespace/resources/keep rules. No original native SDK Maven coordinates are present in generated POMs. Normal source compilation does not read this audit or reference artifacts.

The full normal base receipt passes ABI symbols, raw/final ConstantValue, source-method preservation, class-version/access/bootstrap and D8 min-api 23 gates. Source output includes 43 named compiler switch-map classes, eight source compiler enum-array helpers, 1621 private lambda helpers and 14 exact source helpers. Output removes 335 verified unused implicit Object constructors and one specifically verified nonoriginal default interface bridge; it does not replace any original method body. These are explicitly accounted compiler artifacts, rather than unreported ABI equality claims.

`android/maven/source-provenance` preserves the source-build receipts and packaging inventory alongside the package-local AARs. Every packaged class/Kotlin module is compared byte-for-byte with the verified source-built JAR entries. AGP may change nested JAR archive layout while retaining these entry bytes. Compile-only R classes are excluded; actual IDs belong to the consumer's resource linker. This packaging proof does not establish full native UI, service/account, or physical-device behavior. The original RN wrapper source hashes/adaptations are in RN_PROVENANCE.json; the approved original transport replaces the template's Nitro example.
